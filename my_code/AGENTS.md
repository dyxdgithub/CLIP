# my_code 工作指引

本文件适用于当前 CLIP 项目的 `my_code/`。包结构、公开 API、安装和现有测试说明见根目录的 [AGENTS.md](../AGENTS.md)。
`my_code/` 用于本地训练、评测和数据实验；当前子目录为 `train/`、`test/`、`data/`。

服务器上的项目根目录为 `/media/xyycyc/Elements1/dyx/CLIP`；训练图片按 CSV 中的 `RelativePath` 存放在其下的 `my_code/data/images_all/`，例如 `my_code/data/images_all/Aircraft/Fixed-wing aircraft/<ImageID>.jpg`。启动器使用仓库根目录推导默认图片路径，仍可通过 `IMAGE_ROOT` 覆盖。

## 1. 范围与代码位置

- 只修改当前任务所需文件，不顺带改动无关目录。
- 训练入口放在 `train/`，评测和可视化入口放在 `test/`，数据处理脚本放在 `data/` 或对应数据子目录。
- 实验脚本可以使用 `clip` 包；`clip/` 包代码不应依赖 `my_code/`。
- 可复用的模型或分词逻辑应进入 `clip/`，但只有任务明确要求修改包实现时才跨目录移动代码。
- 创建新目录或共用模块前，先确认现有目录不能清楚承载该职责。

## 2. 可复现的脚本入口

- 从仓库根目录运行脚本。引用本项目包时使用 `import clip`，不要沿用其他项目的 `PYTHONPATH=src` 约定。
- 可配置的输入、输出、模型或 checkpoint、设备及关键运行参数应通过命令行参数提供。
- 在 `--help` 中说明参数接受的值、默认值和作用；不要把开发者机器的绝对路径写死在代码中。
- 训练和评测脚本应允许指定输出目录。有 checkpoint 时，可默认写到脚本旁的 `output/<模式>_<checkpoint>/`。
- 新增或修改可运行的训练、评测脚本时，在同目录维护 `.sh` 启动器：切换到仓库根目录，显式传入复现实验所需参数，并将机器相关路径集中为清楚命名的变量。
- 记录输入来源、模型或 checkpoint、设备、随机种子和关键超参数，便于复现实验。

## 3. 训练、评测与长任务

- 训练脚本应允许选择 GPU 编号；GPU 不可用或任务指定时支持 CPU 路径。
- 训练时分别记录 step 与 epoch 粒度的总损失及各项损失，例如使用 `train_step/*`、`train_epoch/*` 命名空间。
- 验证除了损失，还应计算与任务相符的指标，例如分类准确率或检索 Recall@K，并与训练指标分开记录。
- 长时间运行的下载、转换或数据处理任务应实时显示进度，并保存可恢复状态，避免中断后重复已完成工作。
- 进度信息应包含已完成数量和总量；无法确定总量时明确说明。

## 4. 数据、依赖与凭据

- 数据脚本的默认输入和输出路径应相对于已说明的仓库或脚本目录解析，并允许命令行覆盖。
- 不提交模型权重、数据集图片、下载压缩包、缓存和生成的实验输出。
- API 或 Hugging Face 凭据从环境变量等本地安全来源读取；不要写入源码、日志、示例或文档。
- 新增依赖时更新使用该依赖的环境对应的依赖清单。
- 不把大型下载、全量数据处理、付费 API 调用或完整训练任务当作代码验证步骤；交付时提供用户可执行的准确命令。

## 5. 验证与交付

- 优先做与改动对应的语法检查、单元测试、小样本或合成数据验证，以及 `--help` 检查。
- 修改 `.sh` 启动器后，先运行 `bash -n <启动器>` 检查语法，不因此启动完整任务。
- 本仓库现有一致性测试会加载全部注册模型；运行前先确认权重缓存、网络和计算资源，具体见根目录 [AGENTS.md](../AGENTS.md)。
- 交付时说明改动文件、已执行的检查、未运行的大型任务及其准确运行命令。
- 如果任务要求提交，只暂存本任务文件；规划记录、实现和完成记录应清楚区分。
